# EasyVoca｜500語バッチの見落としがちな意味・用法の調査

Repository: https://github.com/totoro0419/easyvoca

**BATCH_NO: 1**

あなたは単語データ選定担当。今回はアプリ開発ではなく、上記バッチが担当する500語から、見落としやすく学習価値のある別義・別品詞・語法を厳選し、根拠とともにGitHubに保存する。

## 最初に
1. Repositoryの `README.md`、`docs/SELECTION_POLICY.md`、`docs/BATCH_PROTOCOL.md` を読む。変更された最新仕様を優先する。
2. `data/master/words.jsonl` に固定された12,000語マスターが存在し、出典・利用条件が確認済みかを検査する。
3. 担当範囲は `start=(BATCH_NO-1)*500+1` から `end=BATCH_NO*500` まで（両端含む）。マスターの該当番号から正確に500語取得する。**マスターがない場合は推測で500語を選ばず、欠けている前提を報告して終了。**

## 調査・選定
- 各単語で辞書の別品詞・別義・語法を調べるが、収録候補にするのは、一般に知られる意味から見落としやすく、現代英語・大学入試で学習価値があるものに限る。
- 単語自体が簡単であることは必須条件ではない。基礎語から入試上級語まで同じ原則で判定する。
- 単純な言い換え、基本義から容易に推測できるもの、用途の狭い稀な意味はむやみに採用しない。採用件数のノルマを作らない。
- AIの記憶だけで出典を確定せず、アクセスできた辞書・語法資料などで裏付けする。確認できない情報は `unverified` にする。
- 辞書本文・例文を大量に転載せず、根拠リンクと独自の短い日本語説明で記録する。コアイメージと完成版例文の大量生成はこの工程では必須としない。

## GitHubへの保存
- `docs/BATCH_PROTOCOL.md` のスキーマ・命名規則に従い、担当の500番号に対応した
  - `data/review/batch_<start>_<end>.jsonl`
  - `data/candidates/batch_<start>_<end>.jsonl`
  - `reports/batch_<start>_<end>.md`
  を作成する。
- **担当専用の `batch/<start>-<end>` ブランチ**に保存し、`main` 宛のPRを作る。別バッチのファイル・共通仕様・masterは書き換えない。
- 作業は50〜100語単位に分けてコミットしてよい。既に記録済みの単語を再調査せず、未完了から再開する。

## 完了条件
- 対象500番号すべてに、調査済みまたは `needs_review` の状態を正しく記録。
- 500個の番号の欠落・重複がなく、候補の索引と候補件数が一致する。
- 完全検査済みと宣言するのは `needs_review=0` かつ必要な根拠確認ができたときだけ。
- 完了しなければDraft PRと残件明細を保存し、未完了と明記する。根拠未確認を採用済みに偽装しない。
- 最終報告は、担当範囲、調査済み件数、要再調査件数、候補語義数、コミット/PRリンク、問題点を簡潔に示す。

調査や計画だけで終わらず、可能な範囲でGitHubへの実保存と検証まで進める。
