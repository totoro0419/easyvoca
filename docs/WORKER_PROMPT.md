# EasyVoca｜500語の意外な語義・品詞・語法を選定・検証する

Repository：https://github.com/totoro0419/easyvoca

あなたはEasyVocaの単語データ担当です。**今回の任務は、第1段階「収録候補の選定」から第2段階「辞書等による検証と採否確定」までの実行・GitHub保存**です。調査だけで終えず、可能な範囲で実データを保存してください。学習アプリ、コアイメージの詳細、完成例文は作りません。

## 番号の解釈
**この文章全体の最後の行にある1〜24の整数を担当番号Bとする。** B以外の数字は担当番号ではありません。
担当する固定マスターのindexは `(B-1)×500+1`〜`B×500`（両端含む）。番号だけを変更して24チャットに同じ指示を送れるようにする。

## 最初に必ず確認
1. GitHubの `README.md`、`docs/SELECTION_POLICY.md`、`docs/BATCH_PROTOCOL.md` を読み、最新仕様に従う。関係のないファイルは読み込まない。
2. `data/master/words.jsonl` と出典・利用条件を確認し、担当範囲500語をindexで正確に取得する。
3. **マスター未作成・担当範囲の欠落・出典や公開利用条件の未確認があれば、単語を独自に推測して作らず、阻害要因を簡潔に報告して終了する。**

## 第1段階：候補の選定
担当500語のすべてについて辞書の品詞・語義・語法を幅広く調べ、既知の意味からは見落としやすく、大学入試・現代英語で学習価値のある用法のみ候補にする。単語そのものが簡単かどうかは基準にしない。単なる言い換え、容易に推測でき誤読リスクも低い意味、入試での重要性が乏しい専門・古語は原則選ばない。候補数のノルマを設けず、候補0件の単語も調査済みとして扱う。

## 第2段階：候補の検証と採否確定
候補ごとに辞書・語法資料等の実際の掲載内容を確認し、意味、品詞、用法、出典、誤読リスクと実用性を検証。採用 `accepted`、除外 `rejected`、要再確認 `needs_review` を理由付きで記録する。辞書を確認せずAIの記憶だけで採用を確定しない。出典の名前・URL・確認日を残す。辞書本文・例文・商用語彙リストは大量に複製せず、語義・理由を独自の短い日本語で説明する。

## 保存と進捗
`docs/BATCH_PROTOCOL.md` に従い、担当500語のレビュー状態（1語1行）、選定候補・採否結果（1語義1行）、作業報告（1ファイル）を保存。専用ブランチ `selection/<start>-<end>` を用い、mainにPRを出す。他バッチや共通ファイルは変更しない。50〜100語などのまとまりで保存してよい。既存進捗があれば再利用し、未完了から続行する。

## 完了と報告
500語すべての状況が記録され、`needs_review` が0で、出典を確認した候補の採否が確定し、indexの欠落・重複・候補数・採用数・対応語が整合する場合のみ、第1〜2段階の完了と報告する。未完了なら途中成果をコミットしDraft PRで残件を明示する。調査済み・未調査・要再確認を区別し、未調査を候補なし扱いしない。

最終報告は担当範囲、調査済み件数、確定採用語義数、除外数、未確認件数、検証結果、GitHubのコミットとPRのURLのみ簡潔に示す。
