# EasyVoca｜既存500語バッチをAI主体で完成させる【24チャット共通】

Repository：https://github.com/totoro0419/easyvoca

## 目的
以前の調査は、全品詞・全語義を辞書で徹底検証する要求が過剰だったため、多数の単語が未処理になった。**今回はその方式をやめる。** AI自身の英語語彙・文法知識で、担当500語の「見落としやすく学習価値が高い別義・別品詞・語法」を広く発見・選定し、既存の調査成果に補完してGitHubへ保存する。

**500語を一通りAIが判定し、採用候補の精度を保って完了させることを最優先**とする。辞書の全語義の網羅証明は求めない。コアイメージ・例文・学習問題・アプリ開発は行わない。

## 担当番号
このプロンプトの**最終行に後から追加される整数（1〜24）**をBとし、担当範囲は `(B-1)*500+1` 〜 `B*500`（両端含む）とする。固定マスター `data/master/words.jsonl` のその500行のみ対象。単語を変更・追加・並べ替えしない。

## 最初に
1. GitHubの `docs/SELECTION_POLICY.md` と `docs/BATCH_PROTOCOL.md` の**最新版（AI優先方式）**を確認。古い草案の「辞書で全義の確認必須」などと矛盾したら、この指示と最新版を優先する。
2. 自分の既存ブランチ `selection/<開始5桁>-<終了5桁>`、既存Draft PR、`data/review/batch_<開始>_<終了>.jsonl`、`data/candidates/batch_<開始>_<終了>.jsonl`、`reports/batch_<開始>_<終了>.md` を確認。**新しいPRを作らず、既存PRを更新する。**
3. 既に確認・採否を記録した候補と辞書出典は保護する。明らかな誤り・重複・不整合がない限り最初から調査し直さない。

## 実行：AIによる候補選定と採否
- 既存の `needs_review` を優先し、担当500語を50〜100語程度のまとまりで順次スクリーニングする。辞書の全義を逐一読破せず、自分の知識で別義・別品詞・特殊構文・重要な発音差を考える。
- **意外性・誤読リスク・大学入試や現代英語での実用性**が高いものを候補にする。簡単に推測できる言い換え、ほぼ使わない専門義、古語・方言は原則除外。候補数のノルマはない。候補0件は正常。
- **AIが意味・品詞・使い方に高い確信を持てる候補は、辞書検索を省略して採用してよい。** 保存時は `decision: "accepted"`、`verification_method: "ai_judgment"`、`confidence: "high"`、`sources: []` とする。これは外部辞書による独立検証済みを意味しない。
- 自信が弱い候補、品詞・語法に争いがある候補、明らかに珍しい候補のみ辞書等で確認する。実際に確認した出典だけURL・確認日を保存し、`verification_method: "dictionary_checked"` とする。見ていない辞書を見たことにしない。
- 曖昧さが解消しなければ候補の `needs_review` に残す。自信がないのに採用しない。マスター中の誤綴り・略号・固有名詞らしい項目は `master_issue` に記録し、意味を捏造しない。判断可能なものまで「網羅性を証明できない」という理由だけで未完了扱いにしない。
- **実際にAIでスクリーニングした語のみ**レビューの `verified_selected`（採用あり）または `verified_none`（採用なし）に更新し、`screening_method: "ai_judgment"` 等で調査方式を明示する。以前の `needs_review` 500行を確認せず一括で `verified_none` に変更することは禁止。

## GitHub保存と検証
- 既存の候補ID・フィールド・出典と既存PRの履歴を維持し、同じ3ファイルを更新する。共有仕様・マスター・他バッチを変更しない。
- 候補行の必須項目：`candidate_id, index, word, pos, meaning_ja, reason, utility, decision, decision_reason`。AI判断か辞書確認かを区別する。
- 更新済み `scripts/validate_batch.py` は**AI判断による採用を許容**する。既存ブランチの検証スクリプトが旧式の場合、mainの最新版を安全に取り込む。各担当が共通スクリプトを個別改変しない。
- 対象500番号・見出し語の一致、候補ID重複、候補数・採用数、判断と調査方式の整合性を検証する。可能なら `python3 scripts/validate_batch.py B` を実行する。できなければ実行可能な同等チェックを行い、未実行の検査を成功と書かない。
- 検索・作業報告は必要最小限にし、単語の調査とデータ保存に処理量を集中する。複数回に分けてコミットしてもよいが、途中保存だけで終了しない。

## 完成条件
**担当500語をAIで実際にスクリーニングし、発見した候補に採否と判断方式を付け、データ整合性を検査し、既存PRへ保存したこと。** これは「辞書の全語義を完全に確認した」こととは区別する。未解決の曖昧な語・候補だけ `needs_review` として残し、理由と件数を報告する。明らかな単語マスターの異常は別途報告する。

全件が処理できたら既存PRをレビュー可能な状態にし、**勝手にmainへ統合しない**。最後に担当範囲・AI処理済み語数・採用候補数・辞書確認数・要再確認数・実際の検証結果・既存PR URLを簡潔に報告する。調査・提案だけで終わらず、可能な限り実ファイルの更新とコミットまで遂行する。
