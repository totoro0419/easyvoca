# 24バッチ運用仕様 v1

## 必須前提：固定マスター
- `data/master/words.jsonl` に、出典・利用条件を確認済みの12,000語を固定する（現在未作成）。
- 各行には最低限 `index`（1〜12000、連続で重複なし）、`word`、`level`（1〜12）、`source` を持たせる。
- `index` はEasyVoca内の割当番号であり、**アルク公式の1〜12,000位ランキングを意味しない**。SVLはレベルごとに1,000語という区分。
- 単語マスターの作成には権利関係を確認する。公開リポジトリに無許諾の商用リストの丸写しを置かない。
- **固定マスターがない・対象範囲を読み出せない・範囲外が混在する場合は語を推測して着手せず、阻害要因を報告する。**

## 分担
24チャットがそれぞれ固定マスター中の重複しない500行を受け持つ：
- 01: 00001–00500
- 02: 00501–01000
- ...
- 24: 11501–12000

バッチ番号 `B`（1〜24）から `start=(B-1)*500+1`, `end=B*500` を計算する。対外的には開始・終了の両方を表示する。

## ファイル（バッチ固有。共有ファイルは変更しない）
例：`B=1`
- `data/review/batch_00001_00500.jsonl`：500行の調査済み/要再調査ステータス。各行 `{"index":1,"status":"reviewed_none","candidate_count":0}` 等。
- `data/candidates/batch_00001_00500.jsonl`：見落としやすい意味・用法の候補を語義単位で記録。0件も許容。
- `reports/batch_00001_00500.md`：処理件数、採用候補数、未完了件数、使用した根拠・主要な問題、コミット/PR情報。

候補レコードの基本形式（一例）：
```json
{"index":1,"word":"snake","pos":"verb","meaning_ja":"蛇行する","why_surprising":"一般に知られる名詞と異なる品詞","utility":"道路などの動きを表す用法","status":"candidate","sources":[{"name":"source name","url":"https://example.org","checked_at":"YYYY-MM-DD"}]}
```
※index=1と単語の対応は例示で、実際のマスターの割当を意味しない。
- `status` は `candidate` / `accepted` / `unverified` など、選定方針の定義に合わせる。
- 情報源を確認できない候補を `accepted` にしない。
- データはUTF-8・JSON Lines形式。文章の長い辞書引用や転載をしない。

調査ステータス（1単語に1行）：
- `reviewed_candidates`：根拠のある候補が1件以上
- `reviewed_none`：調査したが収録候補なし
- `needs_review`：資料不足または調査未完了

## 実行手順
1. マスターの有無、対象番号の500語、ソース利用条件と選定基準を確認。
2. 500語を内部的には50〜100語程度のまとまりで処理してもよい。辞書の全語義を調査対象にするが、学習用に収録するのは意外で役立つ候補だけ。
3. 各単語の調査ステータスを記録。候補に出典と判断根拠を保存。
4. 担当専用ブランチ `batch/00001-00500` などに保存し、PRを `main` 宛に作る。ほかのバッチや共有仕様を変更しない。
5. 完了判定はレビュー行が対象の500番号を一度ずつ含み、各番号の候補数が候補ファイルと一致し、未完了0件かどうかを照合して行う。
6. 未完了ならPRをDraftとし、残件と阻害要因を報告。完了を偽らない。重複やインデックス欠落があれば修正する。
7. 24PR統合後、12,000個の連続ID・重複なし・採用判定の一貫性・出典とライセンスを横断検査する。

## 同時作業の注意
- 24チャットが同時に `main` に直接書き込まない。
- 共通の進捗表やREADMEを各チャットが書き換えない。
- コミット/PRの成功・検証の成功を実結果なしに宣言しない。
